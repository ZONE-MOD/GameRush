# Dino Rush — Godot Android + Web starter

نسخه پایه بومی Dino Rush با Godot 4.7.2. یک سورس واحد برای خروجی وب و APK اندروید.

## داخل این مخزن چیست؟

```text
game/                       موتور رانر، بازیکن، موانع، مراحل و رابط اصلی
graphics/                   سیستم ظاهرها و پچ‌های اسکین
audio/                      محل موسیقی، افکت و دوبله
 ui/                        مستندات رابط کاربری
 native/                    محل کدهای Kotlin/Java در صورت نیاز
 server/                    قرارداد API و طرح پایگاه داده Cloudflare D1
 config/                    تنظیمات بازی، لینک پنل و کاتالوگ پچ
 .github/workflows/          ساخت خودکار Web و APK و انتشار GitHub Pages
 legacy/                    فایل HTML بتا ۳ برای مرجع انتقال
 tools/                      اسکریپت اعتبارسنجی و ساخت کاتالوگ اسکین
```

## آپلود در GitHub

1. در GitHub یک مخزن جدید با نام `dino-rush` بساز.
2. اگر می‌خواهی لینک بازی برای همه باز باشد، مخزن و GitHub Pages باید دسترسی عمومی داشته باشند؛ مخزن را `Public` انتخاب کن.
3. فایل ZIP را استخراج کن و **محتویات داخل پوشه** را در ریشه مخزن آپلود کن؛ خود ZIP را به‌عنوان یک فایل تنها آپلود نکن.
4. از مسیر `Settings → Pages`، بخش `Build and deployment`، گزینه `Source` را روی `GitHub Actions` قرار بده.
5. به تب `Actions` برو. اجرای workflow با هر Push به شاخه `main` شروع می‌شود. اگر بار اول اجرا نشد، `Run workflow` را بزن.
6. بعد از موفقیت job انتشار، لینک بازی در `Settings → Pages` یا خروجی job با قالب زیر قابل مشاهده است:
   `https://USERNAME.github.io/REPOSITORY/`
7. فایل APK آزمایشی را از اجرای workflow در بخش `Artifacts` دریافت کن: `DinoRush-Android-debug`.

**نکته:** تا زمانی که مخزن را نساخته‌ای و workflow موفق نشده، لینک نهایی واقعی وجود ندارد. من از داخل این گفتگو به مخزن GitHub تو دسترسی ندارم و نمی‌توانم به‌جای تو آن را منتشر کنم. وقتی لینک مخزن را فرستادی، مسیرها و خطاهای Actions را با همان مخزن هماهنگ می‌کنیم.

## ساختار و پچ اسکین‌ها

تمام اسکین‌ها و هلمت‌های موجود بتا ۳ در یک پچ کامل قرار دارند:

`graphics/skin_patches/base_patch.json`

برای هر پچ جدید فقط یک فایل جدید بساز و در `graphics/skin_patches/` قرار بده؛ نام فایل باید با `patch_` شروع شود، مثل `patch_002_winter.json`. قالب آماده در `graphics/skin_patches/templates/patch_TEMPLATE.json` است.

با Push همان یک فایل، GitHub Actions کاتالوگ کامل را از تمام پچ‌ها می‌سازد و آن را در خروجی Pages در `patches/catalog.json` قرار می‌دهد. بازی هنگام اجرا کاتالوگ آنلاین را دریافت می‌کند. برای اسکین‌های مبتنی بر رنگ و شکل procedural، فایل JSON کافی است. برای مدل یا تکسچر اختصاصی، assetها را نیز اضافه کن و schema پچ را توسعه بده.

## اتصال سرور و پنل

لینک پنل آینده در `config/game_config.json` ثبت شده است:

`https://game.amyratfy8.workers.dev`

فعلاً `api_enabled` خاموش است. قرارداد مسیرها، قوانین شناسه شش‌رقمی، نام‌های رزروشده، تیک آبی، سکه، بن زمان‌دار و گزارش مدیریتی در `server/API_CONTRACT_FA.md` و ساختار D1 در `server/schema.sql` آماده شده‌اند. تا وقتی Worker واقعی deploy و آزمایش نشده، این امکانات آنلاین فعال نیستند.

## اجرای محلی در Godot

- Godot `4.7.2-stable` را نصب کن.
- پروژه را با باز کردن `project.godot` وارد کن.
- دکمه Play را بزن.
- کنترل دسکتاپ: Space یا ↑ برای پرش، ↓ یا S برای سرخوردن.
- کنترل لمسی: دکمه‌های پرش و سرخوردن در پایین صفحه.

## محدودیت نسخه پایه

این پروژه یک پیاده‌سازی بومی و قابل‌بازی از هسته رانر است، نه تبدیل خودکار و کامل تمام ۱۴۴ کیلوبایت HTML بتا ۳. فایل HTML اصلی در `legacy/` برای مرجع حفظ شده است. وضعیت دقیق انتقال در `docs/MIGRATION_STATUS_FA.md` آمده است. حساب‌ها در این نسخه دمو محلی هستند؛ هش رمز محلی جای احراز هویت امن سمت سرور را نمی‌گیرد. پرداخت، مالکیت آنلاین، پنل مدیریت و دوبله سینمایی تا اتصال سرویس‌های واقعی فعال نمی‌شوند.
