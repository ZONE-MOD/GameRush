# قرارداد API بازی Dino Rush و پنل مدیریت

این فایل قرارداد پیشنهادی است؛ تا وقتی Worker و پایگاه داده روی Cloudflare پیاده‌سازی و تست نشده‌اند، `api_enabled` باید `false` بماند. صرف قرار دادن URL در سورس، احراز هویت یا مدیریت آنلاین را فعال نمی‌کند.

## آدرس‌های پروژه

- آدرس در نظر گرفته‌شده برای پنل مدیریت: `https://game.amyratfy8.workers.dev`
- پشتیبانی: `@SharkFlux`
- جدول و محدودیت‌های پایگاه داده: `schema.sql`

## قواعد حساب

- ثبت‌نام: نام اکانت + رمز عبور + شماره تلفن.
- ورود: هر سه مقدار نام اکانت + رمز عبور + شماره تلفن باید بررسی شوند.
- شناسه بازیکن باید دقیقاً ۶ رقم و فقط در سرور ساخته شود؛ شناسه محلی نسخه دمو، شناسه سراسری محسوب نمی‌شود.
- نام عادی حداقل ۵ نویسه دارد. بازیکن دارای تیک آبی که فقط مدیر می‌تواند تأیید کند، مجاز به نام حداقل ۳ نویسه است.
- نام کاربری نرمال‌شده باید یکتا باشد و در `reserved_names` باقی بماند تا پس از تغییر نام یا حذف حساب نیز دوباره قابل انتخاب نباشد.
- رمز عبور هرگز به‌صورت متن ساده ذخیره نشود؛ در Worker از KDF مناسب مانند PBKDF2 با salt تصادفی و تعداد تکرار بالا استفاده شود.

## مسیرهای API پیشنهادی

| روش | مسیر | کاربرد |
|---|---|---|
| POST | `/api/v1/auth/register` | ثبت‌نام و صدور شناسه ۶ رقمی |
| POST | `/api/v1/auth/login` | ورود با نام، رمز و شماره |
| GET | `/api/v1/players/me` | دریافت پروفایل و موجودی |
| POST | `/api/v1/players/me/progress` | ذخیره مرحله و پیشرفت |
| GET | `/api/v1/skins/catalog` | دریافت کاتالوگ اسکین‌ها |
| POST | `/api/v1/skins/redeem` | ثبت مالکیت آیتم با کد معتبر |
| POST | `/api/v1/admin/players/{id}/coins` | افزایش یا کاهش سکه |
| POST | `/api/v1/admin/players/{id}/ban` | بن تا زمان مشخص + علت |
| POST | `/api/v1/admin/players/{id}/unban` | رفع بن |
| PATCH | `/api/v1/admin/players/{id}` | تغییر نام یا وضعیت تیک آبی |

تمام مسیرهای `/admin/` باید فقط با نشست مدیر یا توکن مدیریتی سمت سرور قابل دسترسی باشند. کلید مدیر نباید در بازی، فایل‌های GitHub عمومی یا APK قرار بگیرد.

## پاسخ نمونه بن‌شدن

```json
{
  "error": "account_banned",
  "message": "ما طبق بررسی‌های متعدد متوجه شدیم که شما قوانین را نقض کرده‌اید.",
  "player_id": 123456,
  "banned_until": "2026-11-15T12:00:00Z",
  "reason": "توضیح ثبت‌شده توسط مدیریت"
}
```

برای بن دائمی، `banned_until` برابر `null` و `permanent` برابر `true` باشد. زمان باید در UTC ذخیره و هنگام نمایش به زمان محلی کاربر تبدیل شود.

## امنیت و مرز اعتماد

- مقدار سکه، مالکیت اسکین، تیک آبی، شناسه بازیکن و وضعیت بن فقط از سرور معتبر است.
- بازی نباید با تغییر فایل محلی بتواند سکه یا آیتم آنلاین تولید کند.
- تغییر موجودی باید در `coin_ledger` ثبت شود.
- تغییر نام باید نام قبلی را در `reserved_names` نگه دارد.
- کدهای خرید/هدیه باید یک‌بارمصرف و سمت سرور اعتبارسنجی شوند.
